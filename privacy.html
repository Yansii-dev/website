Privacy Policy

Last updated: October 16, 2026

1. Who we are

YANSII ("we", "us", "our") is an AI-assisted security testing Chrome extension created by an independent developer. This policy covers the YANSII browser extension (v3.0.0+) and the yansii.in website.

2. What data we collect

Short answer: almost nothing.

The YANSII extension operates entirely within your browser. We do not operate servers that receive, store, or process your browsing data.

  • Extension scanning data — all scan results, findings, patterns, Intelligence Layer data, and memory are stored locally in your browser using chrome.storage.local. This data never leaves your device. The Free tier includes 55 passive scanners; Pro adds 13 more (68 total) plus 6 framework-specific deep scanners.
  • AI copilot data (Pro) — when you use AI features, page context is sent directly from your browser to your chosen AI provider using your own API key. YANSII never sees it.
  • Email address — if you submit a feedback form or contact us, we collect your email and use it only to respond and for product updates.
  • License key — Pro users receive a license key validated against our licensing provider. We do not receive payment details.
  • License revalidation — License keys are automatically revalidated on extension startup to confirm subscription status. This sends your license key and device fingerprint to api.yansii.in. No other data is sent during this check.
  • Target-domain requests — When the crawler is active, the extension fetches /robots.txt and /sitemap.xml from target domains to respect crawling restrictions and discover URLs. These are standard HTTP requests to the target you are already authorized to test — not to YANSII infrastructure. The content is cached locally per-origin for the crawl session duration.

The use of information received from Google APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements.

3. What we do not collect

  • Browsing history or visited URLs
  • Page content, DOM data, or cookies
  • API keys or credentials you enter
  • Scan results or security findings
  • AI conversation history
  • Analytics or telemetry from the extension
  • Intelligence Layer data (application models, hypotheses, attack chains, scanner weights, session memory)
  • CVSS scores or bounty estimates
  • Custom scanner rules
  • Report contents

4. Browser permissions

YANSII requests Chrome permissions, each justified by a specific feature. Full justification is at PERMISSIONS_JUSTIFICATION.md in the source.

  • activeTab — scan the current tab when you click the icon
  • storage — save findings and settings locally
  • webRequest — analyze HTTP headers
  • cookies — audit cookie security attributes (Pro only)
  • scripting — inject content scripts for DOM analysis
  • alarms — scheduled work such as OOB callback polling

5. AI provider data flow

The AI copilot uses a BYOK model. Page context goes directly from your browser to your AI provider using your key. YANSII does not intercept, proxy, log, or cache these calls. Review your provider's privacy policy.

6. Intelligence Layer (Pro)

The Intelligence Layer is a 6-component system that runs entirely in your browser. It does not make external API calls — all processing uses deterministic algorithms, pattern matching, and Bayesian inference locally.

Application Model

Builds a local profile of each target application (detected framework, endpoints, authentication type, API surface, security posture). All data is derived from HTTP headers, DOM analysis, and scanner output. Stored in chrome.storage.local. Never transmitted externally.

Hypothesis Engine

Generates vulnerability predictions based on the Application Model using local pattern matching and inference rules. No AI API calls — this is deterministic logic running in the browser. Hypotheses are displayed in the dashboard and stored locally.

Chain Synthesis

Links individual findings into multi-step attack chains (e.g., CORS misconfiguration + missing auth = account takeover chain). Runs locally, stored locally.

Adaptive Scanning

Adjusts scanner priorities based on WAF detection, target security maturity, and Bayesian belief updates. Scanner weight adjustments are stored locally. No data is sent externally.

Session Memory

Persists anonymized patterns learned across scanning sessions:

  • Target archetypes (e.g., "React SPA with JWT auth behind Cloudflare")
  • WAF bypass effectiveness data
  • Vulnerability class frequency data
  • Calibration data for scanner accuracy

No PII is stored — only anonymized technical patterns. Data is stored in chrome.storage.local. Memory entries use LRU eviction (capped at 500 entries, decay after 6 months). Cleared by uninstalling the extension or clearing extension storage.

Impact Assessment

Calculates CVSS 3.1 base scores, estimates bounty ranges, and flags relevant regulatory frameworks (GDPR, PCI DSS, HIPAA, SOC 2, CCPA). All calculations run locally. CVSS scores and bounty estimates are approximations, not professional assessments. Regulatory flags indicate potential relevance, not compliance determinations.

Report Generation

Generates vulnerability reports in HackerOne and Bugcrowd submission formats. Reports contain only your own scan findings and are generated locally. Reports are never transmitted to YANSII infrastructure.

7. Deterministic Validation (Pro)

A non-AI code-level validation layer that checks findings for exploitability — XSS context analysis, CORS exploitability, open redirect validation, CSP evaluation, cookie flag verification. Returns confidence levels: confirmed, likely, unconfirmed, or false_positive. Auto-suppresses false positives with specific reasons. Runs entirely locally.

8. Custom Scanner Rules (Pro)

Users can create custom scanning rules in JSON format (regex body/header matching, header checks, cookie checks). Custom rules are stored in chrome.storage.local. Import/export is via local JSON files. No custom rules are transmitted to YANSII infrastructure.

9. Scanner Graph (Pro)

Scanners can trigger other scanners based on findings (e.g., detecting GraphQL triggers the GraphQL deep scanner). This is event-driven automation running locally. No external data transmission.

10. Dashboard

The extension dashboard has 7 tabs: Findings, Recon Intel (endpoints, tech stack, cookies, headers, forms, JS files, subresources), Hypotheses (Pro), Attack Chains (Pro), Adaptive Scanning (Pro), Impact Assessment (Pro), and Session Memory (Pro). All dashboard data is derived from local scan results and stored in chrome.storage.local.

11. Safe Mode

Safe Mode is enabled by default on fresh installs, limiting the extension to passive-only scanning until you explicitly enable active features.

12. Data storage

All extension data — scan findings, settings, Intelligence Layer data (application models, hypotheses, attack chains, adaptive scanning weights, session memory, impact assessments), custom scanner rules, and reports — is stored in chrome.storage.local. Clear it by uninstalling or clearing extension storage. Memory patterns use 6-month decay, capped at 500 via LRU.
