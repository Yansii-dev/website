YANSII Bridge — Connect to Claude Code

Bridge your browser's authenticated session to Claude Code or any MCP-compatible AI agent. Your browser sees the session; Claude Code does the testing.

The YANSII Bridge is a small local server that runs on your machine. It relays data between the YANSII browser extension and Claude Code. Everything stays on your machine — the bridge binds to localhost only and is never exposed to the internet.

Secure by design

The bridge binds to 127.0.0.1 (localhost) only — nothing is exposed to your network or the internet. No auth token is needed for local use. For remote Claude Code (on a VPS), use an SSH tunnel — never expose the bridge directly.

Quick start

Four steps

Requires YANSII Pro, Claude Code, and Node.js on the same machine — or reachable over SSH for a remote setup.

1

Get the bridge

Clone the bridge repo and install its dependencies:

# clone it
git clone https://github.com/Yansii-dev/yansii-bridge

# install dependencies
cd yansii-bridge && npm install

# quick sanity check — starts the bridge manually
node server.js --mcp

That last command is just to confirm it runs — you'll see the startup log below. Stop it with Ctrl+C; Claude Code will start it automatically once configured in the next step.

2

Add the MCP server to Claude Code

Edit your Claude Code config — ~/.claude/claude_code_config.json or a project .mcp.json:

{
  "mcpServers": {
    "yansii": {
      "command": "node",
      "args": ["/full/path/to/yansii-bridge/server.js", "--mcp"]
    }
  }
}

Use your own absolute path — not the placeholder above. Find it by running pwd inside the yansii-bridge folder you just cloned, then append /server.js to that output. Restart Claude Code after saving.

# run this inside the yansii-bridge folder to get your exact path:
pwd
3

Connect the extension

  1. Open the YANSII popup
  2. Go to Claude Code Bridge
  3. The URL is pre-filled: ws://127.0.0.1:7779
  4. Click Test Connection
  5. Click Connect

Status turns: Bridge connected

4

Use it in Claude Code

Ask Claude Code things like:

  • "Check YANSII status"
  • "Show me the findings YANSII detected on [domain]"
  • "Investigate the top YANSII finding using the session data"

How it works

A stdio + localhost-WebSocket hybrid

server.js --mcp runs both transports at once, sharing one in-memory store — findings the extension pushes are instantly readable by Claude Code's MCP tools:

  • stdio ↔ Claude Code — Claude Code launches the bridge as a subprocess and talks to it over stdin/stdout (MCP). No open port at all for this side.
  • localhost WebSocket ↔ browser extension — a WebSocket server on 127.0.0.1:7779 that the extension connects to.

Three modes, depending on your setup:

ModeCommandWhen
A. stdio (recommended)launched by Claude Code via MCP configMost users. No open port.
B. Localhost WebSocketnode server.jsManual/testing on the same machine. Binds 127.0.0.1.
C. Remote via SSH tunnelnode server.js --mcp + reverse tunnelClaude Code on a VPS, browser local.

Mode C — remote setup: run the bridge locally and tunnel it to the VPS. Never expose the port directly.

# local machine:
node server.js --mcp

# from local, open a reverse tunnel to the VPS:
ssh -R 7780:127.0.0.1:7780 you@your-vps

Claude Code on the VPS then reaches the bridge at http://127.0.0.1:7780. The tunnel is encrypted; no public port.

Security

The security model

  • Binds 127.0.0.1 by default. Not reachable from your LAN or the internet.
  • No auth needed for localhost.
  • Binding to a non-localhost --host requires --auth <token>. The server refuses to start on a non-localhost address without a token, and prints a loud warning if you do supply one — this prevents accidentally exposing your session data.
node server.js --host 0.0.0.0                  ❌ refuses to start
node server.js --host 0.0.0.0 --auth SECRET    ⚠️  starts, warns loudly

Sensitive data is opt-in. By default only findings and endpoints are shared — you turn everything else on explicitly, in the popup.

Shared by default

  • Findings (type, severity, URL, detail)
  • Discovered endpoints

Off until you enable it

  • Full API requests/responses
  • Cookie values
  • Page DOM
  • localStorage

Verify it started

What a healthy startup looks like

Whether launched by Claude Code or run manually, a working bridge prints:

WebSocket listening on ws://127.0.0.1:7779
HTTP API listening on http://127.0.0.1:7780

No server, no port

Prefer no bridge? Use Export / Import

Don't want to run a server at all? In the YANSII dashboard, click Export for AI Agent to download a JSON snapshot, then tell Claude Code "Read this file and investigate." Bring results back in with Import from AI Agent. No server, no port, no connection — just a file.
